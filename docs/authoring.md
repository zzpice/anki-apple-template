# 网页制卡

[打开制卡工具](https://zzpice.github.io/anki-template/tools.html) · [项目示例预览](https://zzpice.github.io/anki-template/preview.html) · [模板使用与字段教学](usage.md#填写卡片)

浏览器负责整理和编辑笔记，Anki 负责生成原生卡片与复习排程。工具直接读取 `cards/note-types.json` 的五个类型和字段；不需要账号、API Key 或服务端。本地使用时在仓库根目录运行 `python3 -m http.server 8000`，打开 <http://localhost:8000/tools.html>。请通过 HTTP / HTTPS 打开，双击 HTML 文件不能可靠加载模块与字段定义。

## 从材料到卡片

1. 设置目标牌组，选类型新建笔记。`::` 可表示牌组层级；一个工作空间使用一个目标牌组，章节仍写入字段。
2. 编辑同名字段。富文本支持加粗、斜体、列表、缩进、图片；HTML 模式可填写表格、代码和来源链接。在 HTML 模式或导入数据中，纯文字的 `< > &` 应转义；富文本直接输入文字即可。只切换模式不修改内容时会保留原字段；富文本编辑、粘贴会转换为静态 HTML，去除脚本、事件属性和样式等非支持格式。
3. 检查「待修正」提示，查看编辑预览。搜索正文、章节或标签，按类型筛选；选中多条可添加标签、删除。删除、合并导入、更换遮挡图片或新工作空间后可撤销一次；继续修改内容前使用撤销，普通编辑撤销由字段本身提供；复制笔记获得新的 GUID。
4. 下载 JSON 备份。完成后导出 Anki 导入 ZIP，或在本地用 JSON 生成 `.apkg`。导入 Anki 后核对卡片与媒体，再同步到手机。

Anki 文本导入会跳过模型首字段为空的笔记；思维导图的原生「标题」虽可留空，走 TSV 时须填写，工具会阻止这一情况的导出。保留空标题时使用 JSON 构包，字段语义不变。

工具不会解析 Markdown，也不把章节或标签改造成模板之外的字段。加载示例会创建副本，不复用安装包里的示例 GUID；示例流程图由项目公共媒体提供，无需另行上传。

## 类型与字段

字段用途和填写示例见 [Anki 使用说明](usage.md#填写卡片)，字段名称与顺序以 [公共规格](../cards/note-types.json) 为准。网页录入时注意：

| 类型 | 录入要求 |
| --- | --- |
| 问答 | 问题与答案必填，其他可留空 |
| 选择 | 按 [选择题规则](usage.md#选择) 填写，答案按录入顺序，与预览中的显示字母无关 |
| 填空 | 正文中使用原生 `{{c1::答案::提示}}`，至少一个非空挖空 |
| 图片遮挡 | 工具维护 `Occlusion`、`Image`；题干与补充按原模板填写 |
| 思维导图 | 内容使用普通嵌套列表，挖空放在节点内容中；标题可留空 |

标签使用 Anki 原生标签，空格分隔，支持 `::` 层级。`固定顺序` 保持选择题录入顺序。答案字母不随预览随机排序改写。

填空与导图：先选中文字或图片，再填编号和可选提示，点击「选中文字挖空」。HTML 模式也可选中完整图片标签。相同编号一起遮住，不同编号交给 Anki 分卡。导图可用列表与增加 / 减少缩进建立树；不要把子列表或另一处挖空包进挖空。支持图片答案和普通备注节点。

图片遮挡：选择图片，拖动画矩形；绘制后的下一框默认使用新编号。点选框或编号按钮后可修改分组、删除。相同编号共同生成一张卡片，其他分组仍遮住（原生 `oi=1` 模式）。更换图片会清空这条笔记的旧遮挡；旧媒体保留，避免影响其他笔记。矩形坐标按图片比例保存，导入后可在 Anki 内置遮挡编辑器继续调整。导入的其他原生形状、旋转或模式完整保留，但本页不修改这类字段；请在 Anki 中编辑。

## 预览的含义

问答、选择的编辑预览复用原正背面、公共样式和 `_review.js`；翻面保留已选项，改字段重新开始预览。视口与外观切换不重新创建卡片。

填空、导图预览保留挖空原文；遮挡预览显示图片与补充，遮挡语法可在只读字段中核对。这里不模拟 Anki 的分卡或答案揭示，完整导图交互和遮挡复习请导入 Anki 查看。项目「示例预览」读取官方 Anki 后端生成的 `web/preview-cards.json`；浏览器缺少原生遮挡 API 时提示导入。构包的 `--preview` 同样导出官方渲染 HTML，供维护检查使用，不会覆盖公共示例。

## 保存与备份

工作空间和图片以一个版本化记录保存在当前站点的 IndexedDB，编辑后自动保存。缓存只属于当前浏览器和站点；清理网站数据、隐私模式或换设备可能丢失。JSON 是可迁移的完整备份，请定期下载。下一批材料可点击「新工作空间」，先备份再清空当前笔记和图片；继续编辑前可撤销一次。

保存失败会明确提示，当前页仍可编辑和导出。多标签页同时打开时会检测版本冲突，不覆盖另一页的新版本：先下载本页 JSON，再重新载入，导入并核对合并结果。相同 GUID 的内容按此次导入覆盖，不自动做字段级冲突合并。

最多 5,000 条笔记、1,000 张本地图片；每图最多 10 MiB，JSON 工作空间最多 40 MiB（base64 会增大体积）。这是分批整理工具，接近上限时请导出并分批制卡。支持 PNG、JPEG、WebP、GIF；其他图片格式可转换后使用。图片按内容 SHA-256 命名并去重，字段只保存 Anki 文件名；JSON 包含 base64 原文件，不保存临时 blob URL。删除笔记不会自动删除媒体。音频和其他复杂媒体请在 Anki 中添加。

## 导入已有数据或 AI 结果

「导入」支持完整 JSON、笔记 JSON 数组、同名字段 CSV / TSV。分隔文件使用 UTF-8，下载对应类型的表头后填写；CSV 用双引号包住含逗号、换行或引号的内容，内部引号写两次，挖空中的换行使用 `<br>`。可选列为 `标签`、`牌组`、`GUID`。每份 CSV / TSV 只支持一个类型、一个目标牌组；JSON 可以包含多种类型，但整个工作空间仍共用一个目标牌组。工具自己的各类型 TSV 可以原样再导入。

先「检查导入」再合并。字段结构、类型、重复 GUID、媒体数据等错误会阻止合并；缺答案、挖空或图片等内容问题可作为草稿导入修正，不能直接导出为 Anki 笔记。图片必须引用本地媒体文件名；粘贴清理后失去地址的图片也会提示待修正，请通过「插入图片」重新添加。已有工作空间保持当前牌组。未填写 GUID 的数据生成新身份；相同 GUID 更新原笔记，不能改类型。保留 GUID 便于后续更新和保留排程；需要独立副本时使用「复制笔记」。

完整 JSON 结构如下，`fields` 的键严格对应所选类型，其他类型同理：

```json
{
  "format": "anki-template-workspace",
  "version": 1,
  "deck": "我的制卡",
  "notes": [
    {"guid": "example-note-001", "type": "basic", "fields": {"问题": "为什么练习回忆？", "答案": "强化记忆", "解析": "", "补充": "", "章节": "学习", "来源": ""}, "tags": ["学习"]}
  ],
  "media": []
}
```

笔记数组可省略 GUID 和空的可选字段。从 Anki 导出的文本需按对应类型整理同名字段表头、`标签` 与 `GUID` 列；原有图片可作为草稿导入，再通过「插入图片」重新附加本地文件，替换旧图片引用。遮挡图片使用「选择遮挡图片」，更换后需重新画框。工具不直接读取个人 `.anki2` 集合、已有 `.apkg` 或媒体目录。

「外部 AI 辅助」生成本项目字段格式的提示词。复制到你选择的 AI 对话，再将返回的 JSON 数组带回导入。提示词只在本页生成，不请求任何模型或要求 Key。导入检查只能检查结构和基本规则，事实、答案、来源仍需逐条核对。

## 导入 Anki

1. 在 Anki Desktop 导入本项目 `downloads/anki-template.apkg`，安装五个类型及公共媒体。已有安装时可重新导入更新模板。
2. 从工具导出 ZIP 并解压。每种类型有一份 TSV；`workspace.json` 保留全部草稿和图片。未修正笔记默认阻止导出，主动勾选「仅导出通过检查的笔记」时才省略它们，并在导入说明里列出数量。
3. 按 [Anki 用户数据目录说明](https://docs.ankiweb.net/files.html#user-data) 找到当前配置对应的 `collection.media`，将 ZIP 的 `media/` 文件**平铺**复制进去，不要复制为子目录。
4. 分别导入 TSV。文件头设置类型、HTML、字段名称、标签列、目标牌组列和 GUID 列；仍应检查 Anki 导入界面是否选择了同名类型、字段映射和「允许 HTML」。原生遮挡依赖当前客户端识别对应类型和媒体。
5. 在浏览器或复习界面核对新增 / 更新条数、答案映射、原生分卡、图片与导图，再同步。

官方文本导入说明见 [Anki 手册](https://docs.ankiweb.net/importing/text-files.html)。相同 GUID 更新现有笔记的行为已在本项目测试；导入设置、同名但不同结构的个人类型、用户修改模板等情况请先备份再核对。JSON 不含复习历史；排程保存在 Anki 集合中。

工作空间与 Anki 之间通过导入文件交换内容，不会自动同步。保留 GUID 重新导出、导入可更新笔记；TSV 的目标牌组用于新增卡片，更新通常保留原牌组，迁移已有卡片请在 Anki「浏览」中更改牌组。网页删除笔记不会删除已经导入 Anki 的笔记；删掉挖空或遮挡分组后，应在 Anki「工具 → 空卡片」中检查旧卡片。Anki 中的导出与备份见 [Anki 使用说明](usage.md#在-anki-导出与备份)。

## 生成 .apkg

在仓库根目录运行以下命令，需要 Python 3.12，依赖沿用项目现有官方 Anki 构建环境：

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r scripts/requirements-build.txt
.venv/bin/python scripts/build_package.py --input 我的制卡.json --output build/我的制卡.apkg --preview build/我的制卡预览.json
```

Windows 路径写法见 [维护说明](development.md)。`.apkg` 包含原五个类型、原模板、公共媒体、你的笔记和图片，由官方后端在临时集合中生成，不读取个人 Anki 数据。`--preview` 可省略。生成器要求所有笔记有效，含未完成草稿的 JSON 应先回工具修正，或走 ZIP 的明确筛选流程。输出不能覆盖输入 JSON、公共安装包或公共预览。

生成器不带出复习排程。重新构包保留笔记 GUID，较新的包可更新原笔记并保留已有排程；短时间内同秒构包可能被 Anki 视为同版本，请等待后重建并核对导入报告。

## 验证边界

自动检查覆盖官方 Anki 后端、五类 TSV / JSON / 媒体 / ZIP / `.apkg`、重复导入与排程、Chromium / WebKit 编辑和存储恢复，以及桌面和小屏浅深色布局。具体测试版本由 [CI 矩阵](../.github/workflows/check.yml) 定义。编辑工具使用浏览器原生富文本命令，不同浏览器粘贴与缩进的 HTML 可能不同，可在 HTML 模式核对。

客户端与设备复核项目见 [维护说明](development.md#验证边界)。浏览器排版预览不能代替客户端；高负载工作空间、浏览器存储配额与异常图片也不能仅凭测试保证。
